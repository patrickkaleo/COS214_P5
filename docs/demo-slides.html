System

What CampusGuard does

An incident is logged on a campus area. Staff dispatch a unit, change who may enter, and alert campus until the incident is closed.

Engineering

Fire in the lab. Rooms: Engineering Lab, Lecture Room 2-1, Server Room.

Science

Chemical leak. Rooms: Chemistry Lab, Physics Lab.

Four teams: Security, Medical, Facilities, Communications. Alerts go out on a legacy radio.

State

RoleIn CampusGuard
ContextIncident, CampusArea
StateIncidentState, AccessState
ConcreteStateNewState, AssignedState, MitigationState, ResolvedState
OpenState, RestrictedState, LockedState

Why. A fire or leak is only allowed to move New → Assigned → Mitigation → Resolved if the current status permits it. Area access is the same: Open / Restricted / Locked. An enum plus switch on Incident or CampusArea would put every transition in one place. The current state object accepts or refuses: New stays New until a unit is on the area; Resolved refuses another progress(); Unlock refuses if the building is already open.

Build

C++11, Makefile, Docker

make builds the same binary the container runs. Names are from the domain: CampusArea, DispatchUnit, TeamCoordinator.

docker compose up --build

From the repository root. The log is the fire, then the leak.

Fire

Fire in the Engineering Building

  1. Fire recorded on Engineering in New. Early progress() stays New — nobody on site.
  2. DispatchUnit sends Security. The coordinator tells Medical, Facilities and Communications.
  3. RestrictArea on the building; every room becomes Restricted. IssueAlert hits the radio.
  4. Assigned → Mitigation → Resolved. UnlockArea reopens the tree.
Dispatch

From operator to teams

Operator.run → DispatchUnit.excute → TeamCoordinator.deploy.

Security responds, then notify. The coordinator calls support on the other units. Security never holds Medical.

Alert

The radio does not speak CampusGuard

We call issueAlert(). The existing box only has sendAlert().

IssueAlert → AlertService → AlertServiceAdapter → LegacyAlertService.sendAlert

The adapter points at a stack object in main. It does not create or own the radio.

Leak

Chemical leak in Science

Different building, different incident. The client uses CampusGuardFacade instead of assembling the steps.

  • reportIncident — log, attach, restrict, alert
  • Mitigate before Medical arrives is refused
  • mobilise Medical — dispatch, then Assigned
  • A second lock on an already closed building is refused
  • closeIncident — resolve, unlock, all-clear

The fire already used those same objects without the facade.

Ownership

If you new it, you delete it

  • main creates buildings and deletes them. Building deletes rooms.
  • Area owns AccessState. Incident owns IncidentState.
  • Area does not own incidents. Operator does not own commands. Adapter does not own the radio.
GDB

Two bugs we actually hit

NewState::updateState — first fire.progress() had nobody on site; it now stays New.

Operator::run — a null Command* is rejected instead of calling excute() on 0x0.

docker compose run --rm -it --entrypoint gdb campusguard ./campusguard
docker compose run --rm --entrypoint make campusguard valgrind
